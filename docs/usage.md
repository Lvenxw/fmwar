# 附魔战争 使用说明

面向服主与玩家。装好之后照这份文档走一遍即可;所有坐标/时间/奖励内容都在 `plugins/fmwar/config.yml`,改完执行 `/fmwar reload` 生效。

---

## 一、这是什么

一个场地 PvP 小游戏。玩家在大厅点"加入游戏"按钮 → 进准备房间 → 集体连点准备按钮 → 开局后被随机分散到场地各处 → 互相厮杀。场地内有六个商店 NPC,可以用对局中定时发放的绿宝石换装备;六个奖励箱里放着一行随机的高级附魔装备。倒计时归零后仍在场地内的人每秒掉血,最后活下来的人获胜。

**核心规则一句话**:进场前的物品会被扣下,进场后拿到的一切都不能带出场。

---

## 二、管理员:首次部署

### 1. 安装

1. 把 `fmwar-1.0-SNAPSHOT.jar` 放进服务端 `plugins/`。
2. 重启服务器(或 `/reload confirm` 不推荐,建议重启)。
3. 首次启动会生成 `plugins/fmwar/config.yml`。
4. 装好 [ExtraShop](https://此处替换为你服的 ExtraShop 下载页)(可选但推荐):没有它游戏照常运行,只是场地里不会出现商店 NPC。

### 2. 部署前置检查清单(逐条确认)

| # | 检查项 | 怎么确认 | 不满足会怎样 |
| --- | --- | --- | --- |
| 1 | `config.yml` 的 `world` 与服务器实际世界名一致 | 看控制台是否有"配置世界 xxx 未加载" | 所有传送与奖励箱失效,控制台报错 |
| 2 | 六个商店 `fmcm1`..`fmcm6` 已在服务器上定义并摆放 | 启动日志会给出结论;`/fmwar doctor` 看 `defined=true` | 场地里不出现商店 NPC,其余玩法正常 |
| 3 | 奖励箱里的自定义附魔键在本服注册表中存在 | `/fmwar doctor` 会逐个列出未注册的键 | 该条被跳过,箱子里的物品变少(控制台 WARNING) |
| 4 | 领地传送权限按需配置 | 大厅可常态开放;准备房间常态关闭、入队期间放行 | 权限过严会挡住玩家,过松则玩家可自行传进场地 |
| 5 | 三个按钮的实际方块坐标与配置一致 | **`/fmwar button` 查看,用 `/fmwar button join` 就地校准**(见第六节) | 点按钮没反应 |
| 6 | 奖励箱坐标处是空气或可替换方块 | 看控制台是否出现"被 X 占用且不可替换" | 该箱子被跳过 |

### 3. 指令一览

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/fmwar` | `fmwar.admin` | 显示帮助 |
| `/fmwar status` | `fmwar.admin` | 当前阶段、队列人数、对局名单、场地内存活数、剩余时间、你自己的队伍 |
| `/fmwar doctor` | `fmwar.admin` | 配置校验 + 每个商店的 `defined/spawned` + **每个附魔键是否已注册** |
| `/fmwar reload` | `fmwar.admin` | 重新加载配置。**校验不通过会保留上一份可用配置**并报错 |
| `/fmwar button` | `fmwar.admin` | 列出四个按钮的坐标,并可点名字进入校准 |
| `/fmwar start` | `fmwar.admin` | 跳过准备按钮,把准备房间内已入队玩家直接拉入对局(调试用) |
| `/fmwar stop` | `fmwar.admin` | 中止当前对局并清场 |

权限:`fmwar.admin` 默认仅 OP;`fmwar.play`(点按钮)默认所有人。

## 三、玩家:怎么玩

### 加入游戏

1. 走到**大厅**,右键"加入游戏"按钮(默认坐标 `-880 103 -1711`)。
2. 你被传送到**准备房间**,并进入游戏队列。聊天栏会提示 `[附魔战争] 你的ID 加入游戏队列`。
3. 准备房间内**至少要有两个人**,否则准备按钮不会生效。
4. 任意人在准备房间右键"准备"按钮(默认 `-886 96 -1711`)连续 **7 次**,准备完成,10 秒倒计时后开局。
   - ⚠️ **倒计时期间有任何人进入准备房间,进度会重置**。
   - 准备房间内人数掉到两人以下,倒计时也会取消。
5. 想退出:右键"返回大厅"按钮(`-879 96 -1711`),或直接走出准备房间——**走出房间会自动退出队列**。
6. 掉线会自动退出队列;重新上线时会被送到大厅。

### 开局瞬间发生了什么

- 你被随机传送到场地内某处(以 `-1078 -1774` 为圆心、半径 100 格,玩家之间至少间隔 25 格,落点取最高可落脚点且不含水面)。
- **背包被清空、药水效果被清除**(进场前的物品被扣下,离场时归还)。
- 获得 5 秒抗性提升 V,血量与饱食度回满,并获得一把**三附魔钓鱼竿**(lure 255 / luck_of_the_sea 255 / magic_detection 5)。
- 右侧出现记分板:剩余时间(900 秒倒计时)与存活人数。

### 对局中

| 事件 | 说明 |
| --- | --- |
| 每 30 秒 | 背包里获得 **1 颗绿宝石**,可到场地内的商店 NPC 处换取物品 |
| 六个奖励箱 | 分布在场地各处,每个箱子随机放着**一行**高级附魔装备(下界合金剑/斧、重锤、三叉戟、长矛、弩、弓、头盔、胸甲、钓竿等) |
| 剩余 60 秒 | 所有存活玩家被传送到**决斗圈**(以 `-1311 -1740` 为圆心、半径 40 格) |
| 倒计时归零 | 仍在场地内的玩家**每秒扣除 2 点血量**,直到决出最后一人 |

### 观战

- 对局开始后,在大厅右键"观战"按钮(`-881 103 -1708`)进入观战模式(旁观者视角,传送到场地)。
- 观战者离开场地范围 → 自动送回大厅并恢复生存模式。
- 观战者掉线 → 若对局仍在进行,重新上线后**仍是观战模式**;若对局已结束,上线后被送回大厅。

### 结束条件

| 情况 | 结果 |
| --- | --- |
| 场地内只剩 1 名玩家 | 该玩家**获胜**,游戏结束 |
| 场地内一个人都不剩(如同时死亡) | **无人生还**,游戏结束 |
| 你死亡 | 背包清空、移出游戏、传回大厅,广播 `你的ID 死亡` |
| 你走出场地范围 | 同上,广播 `你的ID 离开了游戏` |
| 你掉线 | 视为离开游戏,广播 `你的ID 离开了游戏`;重新上线后在大厅 |

### 结算时

- 场地内所有实体被清除(奖励箱、掉落物、箭矢、载具等),商店 NPC 被移除。
- 所有参与者被传回大厅,**进场前的背包会归还**;对局中获得的物品不会带出。
- "加入游戏"按钮重新生效,"观战"按钮失效。

### 需要知道的限制

- 在提示接收范围内**不能骑马/坐船/骑在其他玩家头上**(会被取消)。
- 服务器重启会**作废当前对局**,插件停用时会强制清场:移出队伍、还原计分板、移除奖励箱与商店、把玩家送回大厅。
- 坐在/躺在某个道具上(如 GSit 类插件提供的姿势)是否被禁止,取决于该插件是否另接了拦截。

## 四、配置速查

`plugins/fmwar/config.yml` 的主要段落:

| 段落 | 作用 |
| --- | --- |
| `world` | 游戏所在世界 |
| `regions` | 场地 / 提示接收范围 / 准备房间 / 大厅 / 决斗圈,各写 `min`+`max` 两个角点(顺序无所谓,自动归一化) |
| `locations` | 三个传送点,可带 `facing` 朝向点 |
| `buttons` | 四个按钮的方块坐标与容错半径 |
| `timing` | 准备次数(7)、准备倒计时(10s)、对局时长(900s)、决斗圈传送阈值(60s)、绿宝石间隔(30s)、归零扣血(2) |
| `disperse` | 开局分散:中心、半径、最小间距 |
| `duel` | 决斗圈:中心、半径、落点最小间距 |
| `start` | 开局清背包/清效果、抗性时长与等级、回满血食、钓竿及其附魔、是否归还入场背包 |
| `emerald` | 每次发放的绿宝石数量 |
| `chests` | 奖励箱坐标 + 内容行(每箱随机取一行) |
| `extra-shops` | ExtraShop 集成的开关注与六个 shopId |
| `teams` / `scoreboard` | 队伍名、记分板标题与两行文本 |
| `messages` | **全部提示文案**,支持 `&` 颜色代码与 `{player}` 等占位符 |

### 奖励箱内容怎么写

```yaml
chests:
  loot-groups:
    - - 'NETHERITE_SWORD:overlay_network=6'        # 单物品,附魔等级 6
    - - 'MACE:doom_hammer=1,wind_burst=1'          # 多个附魔用逗号
    - - 'BOW:eternal=1'
      - 'TIPPED_ARROW:potion=instant_damage;amplifier=1'   # 药水箭
```

- 格式:`<材质>[:<片段>[;<片段>...]]`,附魔片段是 `[命名空间:]键=等级`,缺省命名空间为 `minecraft`。
- **每个箱子独立随机取一行**,只放这一行的物品。
- 自定义附魔(数据包/附魔插件提供的)必须写完整键。写错的键会让该条目被跳过并记 WARNING —— 用 `/fmwar doctor` 可提前查出。

## 五、故障排查

### 点"加入游戏"按钮没反应

**头号原因:世界名写错。** 本插件所有区域、传送点、按钮、奖励箱都只在 `world` 指定的世界里生效。若场地其实在 `game` 世界而配置写的是 `world`,插件不会报错,但按钮判定、区域判定、传送全部静默失效——症状就是"点按钮没反应",甚至"站在场地里被判离场"。

- **怎么发现**:启动日志会打印 `游戏世界 X 已就绪（当前 N 名玩家）`;若目标世界不存在会直接报错(SEVERE),若存在但**里面一个人都没有**会 WARN 提醒你核对世界名。
- **怎么修**:把 `config.yml` 的 `world:` 改成场地所在世界的实际名字,再 `/fmwar reload`。

确认世界无误后,按顺序继续排查,每一步都有明确结论:

1. **确认按钮坐标是否对齐**(第二常见原因)。执行 `/fmwar button`,看 `join` 列出的坐标是否与你右键的**方块**坐标一致;
   不一致就用 `/fmwar button join` 校准(第六节)。
   - 注意:按钮贴墙/贴地时,`PlayerInteractEvent` 返回的是**被点中的那一格**,可能与你以为的坐标差一格。这就是容错半径存在的理由(默认 2.0 格)。
2. **确认在聊天栏有没有看到提示**。以下几种情况会给出文字说明而不再是沉默:
   - `游戏已经开始,暂时无法加入` → 对局进行中或准备倒计时中,等下一局。
   - `你已经在游戏队列中,无需重复点击` → 你已在队列里。
3. **确认玩家有 `fmwar.play` 权限**(默认所有人)。若你服上用权限组管理,检查是否被显式设为 false。
4. **确认插件已启用**:控制台应有 `附魔战争已启用`。

### 准备按钮点了没反应

- 准备房间内**已入队人数不足 2 人**时会提示 `准备房间内至少需要两名已入队玩家`。
- 每次点击都会在动作栏显示进度 `准备中 3/7`;满了之后进入 10 秒倒计时。
- 倒计时中有人进入准备房间会重置进度并提示。

### 场地里没有商店 NPC

- 跑 `/fmwar doctor`,看每个 shopId 的 `defined` 是否为 true。
- `defined=false` 表示服务器上还没配置这个商店:**本插件无法创建商店**,只能让已存在的商店出现/消失。请先用 `/eshop` 在其真实坐标上创建。
- 完全不需要商店时,设 `extra-shops.enabled=false`,启动时就不会再有相关提示。

### 奖励箱里物品变少

- `/fmwar doctor` 会列出**未注册的附魔键**。这些键需要数据包或附魔插件提供,写错或缺失时该条目被跳过。
- 若提示某坐标"被 X 占用且不可替换",说明该处已有方块,箱子被跳过;换个坐标或清掉那个方块。

### 控制台刷 `未找到商店` / `商店移除失败`

- 出现在插件停用或对局结束时,说明配置里有商店未被定义。**新版本已改为静默跳过**;若仍看到,请确认用的是最新构建。
- 想彻底消除,设 `extra-shops.enabled=false` 或把商店配置好。

### `reload` 报"配置存在 N 个问题,已保留上一份可用配置"

- 你的 `config.yml` 缺少关键项(被清空、截断,或被其它插件整份覆盖)。旧配置仍在生效,不会影响进行中的对局。
- 按报错里列出的路径补回内容再 reload。若文件被清空,删掉它让插件重新生成默认文件。

### 玩家报"我明明在场地里却被判离场"

- 检查 `regions.arena` 是否覆盖了实际活动区域,以及 `world` 是否一致。
- 注意场地判定是**标称坐标**判定(y 也在范围内),垂直方向超出 `max.y` 也会被判离场。

## 六、按钮就地校准(推荐给服主)

按钮坐标最容易出错,所以提供了游戏内校准:

1. 站在目标按钮旁,执行 `/fmwar button`。
2. 聊天栏会列出四个按钮及当前坐标;点击其中一个按钮名(如 `join`)。
3. 聊天栏提示:`请在 30 秒内右键一次目标方块,把它登记为按钮 join`。
4. **右键一次那个按钮方块**。插件会:
   - 把该方块坐标写入 `config.yml` 的 `buttons.join.blocks`;
   - 立即重新加载配置使其生效;
   - 在聊天栏回显写入的世界/坐标/方块类型。
5. 用 `/fmwar button` 再确认一次。

同一个按钮支持登记多个方块(例如大厅里放了两个加入按钮):重复第 2–4 步即可,坐标会累加进 `blocks` 列表。

## 七、给开发者的备注

- 构建:`gradle build` 产出 `build/libs/fmwar-1.0-SNAPSHOT.jar`。
  仓库自带的 wrapper 固定 Gradle 9.4.0,而 `run-paper` 要求 ≥9.7,因此默认不加载 `run-paper`;
  需要 `runServer` 时先升级 wrapper 再用 `gradle -PwithRunPaper=true runServer`。
- `libs/ExtraShopApi-1.0.1.jar` 只作编译期依赖,**不要**放进 `plugins/`,也不要 shade 进本插件。
- 设计决策见 `docs/adr/`,领域词汇见 `GLOSSARY.md`,部署清单见 `docs/install.md`。
